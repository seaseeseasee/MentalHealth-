# Phase 4–5: สรุปการพัฒนาและผลการทดสอบ

## การตัดสินใจที่ใช้ (ค่าตามที่เสนอในรายงาน Phase 1–2)

- เพิ่มตารางตามข้อ 6 (`users.role`, `assessment_attempts`, `usage_events`, `assessment_settings`, `app_settings`, `admin_audit`) แบบเพิ่มอย่างเดียว ไม่แก้หรือลบข้อมูลเดิม
- ไม่ติดตั้ง library ใหม่: กราฟ SVG เขียนเอง, Excel ใช้ CSV, PDF ใช้การพิมพ์ของเบราว์เซอร์, test ใช้ `node:test`
- บทบาท: `admin` (แก้ไขได้) และ `analyst` (ดูอย่างเดียว)
- ซ่อนกลุ่มย่อยที่มีน้อยกว่า 5

## การตั้งผู้ดูแลระบบคนแรก

```bash
# ใน .env
ADMIN_EMAILS=you@example.org
```

หรือบนเซิร์ฟเวอร์ (หลังผู้ใช้สมัครแล้ว):

```bash
docker compose exec api node --disable-warning=ExperimentalWarning src/cli.ts set-role you@example.org admin
```

จากนั้นเข้า `/admin` หรือกดลิงก์ "แดชบอร์ดผู้ดูแลระบบ" ในหน้าหลัก/โปรไฟล์

## สิ่งที่ต้องตัดสินใจก่อนใช้งานจริง

1. **ความยินยอมของผู้ใช้เดิม** ข้อความ PDPA เดิมระบุว่าข้อมูล "ใช้เพื่อแสดงผลให้คุณเท่านั้น" ผมแก้ข้อความสำหรับผู้สมัครใหม่ให้ระบุว่าผู้ดูแลระบบเห็นสถิติรวมแบบไม่ระบุตัวบุคคล แต่ผู้ใช้ที่สมัครก่อนหน้านี้ยินยอมภายใต้ข้อความเดิม ควรให้ผู้รับผิดชอบด้าน PDPA ตัดสินว่าจะ (ก) แจ้งและขอความยินยอมใหม่ (ข) ไม่รวมข้อมูลก่อนวันเปลี่ยนนโยบาย หรือ (ค) ถือว่าสถิติแบบไม่ระบุตัวบุคคลอยู่ในขอบเขตเดิม
2. **สำรองข้อมูลก่อน deploy** การเริ่มระบบครั้งแรกจะเพิ่มคอลัมน์ `users.role` และตารางใหม่ (ไม่แก้ข้อมูลเดิม) แต่ควร backup volume `mindease-data` ก่อน

## สิ่งที่ยังไม่ได้ทำ

- การนับผู้เข้าชมที่ยังไม่ล็อกอิน (หน้าแรก) — ต้องใช้ cookie/ตัวระบุแบบไม่ระบุตัวตนเพิ่ม จึงยังไม่ทำเพื่อไม่เก็บข้อมูลเกินจำเป็น
- หน้าอื่นของผู้ใช้ (รายละเอียดแบบประเมิน ดูแลใจ โปรไฟล์ เข้าสู่ระบบ) ได้ธีมสีใหม่จาก token แต่ไม่ได้จัด layout ใหม่
- ตัวละครอวตารแบบปรับแต่งได้ของเดิมยังเป็นภาพ SVG สไตล์เดิม ใช้คู่กับภาพประกอบใหม่
